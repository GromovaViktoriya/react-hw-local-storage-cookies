# 1. В чем разница между localStorage, sessionStorage и cookie?
* localStorage: Постоянное хранилище на уровне домена. Данные живут бессрочно, пока пользователь или скрипт их не удалит. Общие для всех вкладок одного сайта (до 5–10 МБ).
* sessionStorage: Сессионное хранилище. Данные изолированы строго для конкретной вкладки и удаляются сразу при ее закрытии (до 5–10 МБ).
* Cookie: Маленькие фрагменты данных (до 4 КБ), которые автоматически отправляются на сервер с каждым HTTP-запросом. Имеют настраиваемое время жизни (Max-Age / Expires).
# 2. Что и где хранить?
* localStorage:
Настройки интерфейса (тема оформления, язык).
Состояние сайдбара и нечувствительные к безопасности кэши.

* sessionStorage:
Временные данные многошаговых форм и чекаута.
Локальные фильтры и сортировки списков в пределах вкладки.

* Cookie:
Идентификаторы сессий и токены доступа (особенно с флагом HttpOnly).
UTM-метки, аналитика и технические маркеры трекинга.

# 3. Риски хранения токена в браузере
* Уязвимость к XSS-атакам: Если на сайте есть уязвимость для внедрения стороннего JavaScript-кода, злоумышленник может прочитать токен одной строкой (localStorage.getItem('token')).
* Доступ для расширений: Любое стороннее расширение браузера с правами на чтение страницы может получить доступ к данным в localStorage и sessionStorage.
* Отсутствие HttpOnly: В отличие от cookie, веб-хранилища всегда доступны для чтения через скрипты, что исключает защиту на уровне браузера.

## Сборка и развертывание (CI/CD)
### Локальная сборка
Для подготовки проекта к публикации используется стандартный сборщик Vite.
*   **Build command (Команда сборки):** `npm run build`
*   **Output directory (Папка с результатом):** `dist/`

После выполнения команды сборки в корне проекта появится папка `dist`, содержащая оптимизированные статические файлы (HTML, CSS, JS), готовые к загрузке на любой хостинг.

### CI/CD Пайплайн
Проект поддерживает гибкое развертывание на различных платформах:

*   **GitHub Pages:** Деплой осуществляется через пакет `gh-pages`. Команда `npm run deploy` автоматически запускает сборку (`predeploy`) и пушит содержимое папки `dist` в отдельную ветку `gh-pages`. GitHub Pages автоматически раздает файлы из этой ветки.
*   **Netlify:** Настроен на бесшовную интеграцию. При привязке репозитория Netlify автоматически отслеживает изменения в основной ветке, выполняет команду `npm run build` и публикует содержимое папки `dist`. Относительный путь `base: './'` в конфигурации Vite гарантирует корректную работу статических файлов на обеих платформах одновременно.

## Переменные окружения (Environment Variables)

Для безопасного хранения чувствительных данных (например, API-ключей, базовых URL) и конфигураций, зависящих от среды выполнения, проект использует встроенную поддержку переменных окружения Vite.

### Как добавить переменные без хардкода:

1.  Создайте файл `.env` в корневом каталоге проекта (этот файл должен быть добавлен в `.gitignore`, чтобы ключи не попали в публичный репозиторий).
2.  Объявите переменные. В Vite все переменные, которые должны быть доступны в клиентском коде React, **обязательно** должны начинаться с префикса `VITE_`.

```env
# Пример содержимого файла .env
VITE_API_BASE_URL=[https://api.example.com](https://api.example.com)
VITE_SECRET_TOKEN=your_secure_token_here
