# Д/з localStorage, sessionStorage и cookie.
* Ссылка на прод:

# 1. В чем разница между localStorage, sessionStorage и cookie?
* localStorage: Постоянное хранилище на уровне домена. Данные живут бессрочно, пока пользователь или скрипт их не удалит. Общие для всех вкладок одного сайта (до 5–10 МБ).
* sessionStorage: Сессионное хранилище. Данные изолированы строго для конкретной вкладки и удаляются сразу при ее закрытии (до 5–10 МБ).
* Cookie: Маленькие фрагменты данных (до 4 КБ), которые автоматически отправляются на сервер с каждым HTTP-запросом. Имеют настраиваемое время жизни (Max-Age / Expires).
# 2. Что и где хранить?
* localStorage:
Настройки интерфейса (тема оформления, язык).
Состояние сайдбара и нечувствительные к безопасности кэши.

* sessionStorage:
Временные данные многошаговых форм и чекаута.
Локальные фильтры и сортировки списков в пределах вкладки.

* Cookie:
Идентификаторы сессий и токены доступа (особенно с флагом HttpOnly).
UTM-метки, аналитика и технические маркеры трекинга.

# 3. Риски хранения токена в браузере
* Уязвимость к XSS-атакам: Если на сайте есть уязвимость для внедрения стороннего JavaScript-кода, злоумышленник может прочитать токен одной строкой (localStorage.getItem('token')).
* Доступ для расширений: Любое стороннее расширение браузера с правами на чтение страницы может получить доступ к данным в localStorage и sessionStorage.
* Отсутствие HttpOnly: В отличие от cookie, веб-хранилища всегда доступны для чтения через скрипты, что исключает защиту на уровне браузера.
